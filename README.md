# AppiahCo — OCI Terraform Repository

This repository contains tenancy-level infrastructure:

1. A compartment named `free-compartment`
2. A network (VCN) with internet connectivity named `free-vcn` generated by the VCN wizard.
3. A compute instance sized to the entire Always Free allowance.
4. An Object Storage bucket in the tenancy root holding this configuration's own
   remote state.

Terraform manages the tenancy, not what runs on the instance. Nothing here
installs software, and there is no `user_data` or configuration management step:
the instance comes up as stock Ubuntu with your SSH key, and everything after
that is done on the box. What Terraform *does* decide is the one thing you
cannot fix from inside the box — which packets are allowed to reach it.

## What Runs On It

The configuration is neutral, but it is shaped around four workloads sharing the
one host. If you clone this to run something else, the ports are the only part
that needs rethinking.

| Workload | What it is | Inbound ports it needs |
|:---------|:-----------|:-----------------------|
| **Dokploy** | Self-hosted PaaS; deploys containers, fronted by Traefik | 80/tcp, 443/tcp, 443/udp — plus 3000/tcp temporarily |
| **Tailscale** | Mesh VPN for administrative access | None |
| **Minecraft** | Game server, Java and/or Bedrock | 25565/tcp (Java) or 19132/udp (Bedrock) |
| **Hermes (Nous Research)** | Local AI agent with messaging integrations | None |

Three of the four need nothing beyond what Dokploy already opens. That is the
point of the table: "no rule" is a decision, and
[terraform.tfvars.example](terraform.tfvars.example) spells out the reasoning
inline so it does not later read as an oversight.

### Dokploy

Dokploy runs Traefik as its ingress and routes by `Host` header, so every web
application on the box — Dokploy's own dashboard included — shares 80 and 443.
Adding an application does not mean adding a port; it means adding a domain in
the Dokploy UI. 443/udp is HTTP/3 over QUIC, which Traefik's installer publishes
alongside the TCP listener.

A request to the raw public IP on 80 or 443 matches no configured router and
returns **404**. That is Traefik answering. It is evidence the ingress is alive,
not evidence something is broken.

The dashboard on **3000/tcp is a bootstrap rule with a short life**. A fresh
Dokploy install has no account and does not ask for one, so whoever reaches port
3000 first owns the server — never open it to `0.0.0.0/0`, only to the address
you are sitting at. Once the first account exists and Dokploy has a domain of its
own on 443, delete the entry. Leaving it serves the same dashboard over plain
HTTP, with session cookies and passwords in cleartext, to whatever address the
allowlist has aged into.

Removing the NSG rule does not unbind the port — Dokploy publishes 3000 with
`mode=host`, so Docker still listens on it. The dashboard stays reachable
through a tunnel:

```bash
ssh -L 3000:localhost:3000 ubuntu@$(terraform output -raw instance_public_ip)
# then http://localhost:3000
```

Test that tunnel *before* removing the rule. The domain is the normal way in,
and a failed certificate renewal should be an inconvenience rather than a
lockout.

### Tailscale

Tailscale needs no ingress rule, and adding one would not help. `tailscaled`
dials the coordination server outbound over 443/tcp, negotiates direct peer
connections by UDP hole punching, and falls back to DERP relays over 443 when a
NAT defeats that. NSG rules are stateful, so replies arrive on flows the host
itself opened.

Admitting 41641/udp can improve the odds of a *direct* rather than relayed peer
connection, but this instance has a public IP and hole punching generally
succeeds without it. Add it only if `tailscale status` shows peers stuck on
`relay`.

Two operational notes:

- Node keys **expire after 180 days** by default. Disable key expiry for this
  node in the Tailscale admin console, or the server silently drops off the
  tailnet roughly six months after you set it up.
- Once the tailnet is proven to survive a reboot, the valuable change is the
  opposite of opening a port: empty `ssh_ingress_cidr_blocks` and delete the
  dashboard rule, and reach both over the tailnet. A residential address is a
  lease, not an identity — when the ISP rotates it, an allowlist entry starts
  admitting whoever received it next.

### Minecraft

Minecraft is not HTTP, so Traefik cannot route it by hostname the way it routes
the web applications. The container publishes the port on the host directly —
Dokploy's **Advanced → Ports**, not a domain entry — and the NSG rule is what
lets the internet reach it.

| Edition | Port | Notes |
|:--------|:-----|:------|
| Java | 25565/tcp | Pure JVM; runs natively on aarch64. Budget 2–4 GB of heap. |
| Bedrock | 19132/udp | Mojang publishes the Bedrock Dedicated Server as an x86-64 Linux binary, so Ampere A1 needs an emulation layer such as `box64`. Verify this before planning around it. |

**RCON (25575/tcp) must never be published.** It authenticates with a plaintext
password over an unencrypted socket. Bind it to `127.0.0.1` in the container's
port mapping and reach it over an SSH tunnel.

### Hermes (Nous Research)

Hermes gets no inbound rule. Its dashboard binds to `127.0.0.1` and its
messaging integrations are outbound, so nothing needs to reach it from the
internet; reach the dashboard over an SSH tunnel the same way as Dokploy's.

It runs with `network_mode: host`, which is the part worth being careful about:
anything it binds to `0.0.0.0` lands directly on the host's network stack,
behind nothing but this NSG. Keep `API_SERVER_HOST` on localhost. If a webhook
ever genuinely needs inbound access, it is HTTP — give it a domain through
Traefik on 443 rather than a port of its own.

### Fitting all four on one box

12 GB total, and the operating system wants some of it. Rough working budget:

| Component | Memory |
|:----------|:-------|
| Ubuntu 24.04 Minimal + Docker | ~1 GB |
| Dokploy (Traefik, Postgres, Redis, its own UI) | ~1–1.5 GB |
| Tailscale | negligible |
| Minecraft Java, 4 GB heap | ~4.5 GB with JVM overhead |
| Hermes | ~1 GB, more if it runs a local model |
| **Remaining for deployed applications** | **~4 GB** |

A local LLM is what breaks this. Ampere A1 has no GPU, and a model large enough
to be interesting will exhaust both the memory and the two OCPUs. Point Hermes
at a hosted API instead unless you are deliberately experimenting with a small
quantized model.

Everything on the boot volume — Minecraft worlds, Dokploy's Postgres,
`/etc/dokploy` — is unprotected against instance loss. No backup policy is
attached (see [Compute Instance](#compute-instance)), so arrange your own copy
off the box for anything you would miss.

## Network Topology

| Resource                       | Purpose                                                             |
|:-------------------------------|:--------------------------------------------------------------------|
| VCN (`10.0.0.0/16`)            | Regional virtual network in `free-compartment`                      |
| Public subnet (`10.0.0.0/24`)  | Reachable from the internet through the internet gateway            |
| Private subnet (`10.0.1.0/24`) | No public IPs on VNICs                                              |
| Internet gateway               | Bidirectional internet path for the public subnet                   |
| NAT gateway                    | Outbound-only internet path for the private subnet                  |
| Service gateway                | Private path from the private subnet to the Oracle Services Network |

Ingress is enforced per-VNIC by a network security group, not by the subnet:

- **Instance NSG** ([nsg.tf](nsg.tf)) — the only thing that admits traffic to the
  host. ICMP type 3 code 4 from `0.0.0.0/0` and ICMP type 3 from the VCN for path
  MTU discovery, port 22 from `ssh_ingress_cidr_blocks`, and whatever
  `published_ports` opens. Egress is unrestricted.
- **Public subnet** — the VCN's default security list, with no ingress rules at
  all and unrestricted egress. Security lists and NSGs are unioned by OCI, so a
  rule left on the subnet would apply to every VNIC in it. Keeping it empty makes
  the NSG the single ingress control and leaves anything else placed in the
  subnet default-deny.
- **Private subnet** — its own security list: SSH from the VCN CIDR block, the two
  ICMP rules, unrestricted egress. Currently unused.
- Routing: the public subnet defaults to the internet gateway; the private subnet
  defaults to the NAT gateway, with a more specific Oracle Services Network route
  through the service gateway.

The public subnet uses the VCN's default route table and default security list,
as the VCN wizard arranges it. The wizard's rule set is not kept: it opens SSH to
`0.0.0.0/0`.

An NSG is also the only firewall Docker cannot route around. Publishing a
container port writes DNAT rules into iptables ahead of the chains `ufw` and
`firewalld` manage, so a published port can be reachable from the internet even
when the host firewall is configured to refuse it. With Dokploy on the box, that
is not a hypothetical: this NSG is the perimeter.

### Opening a Port

`published_ports` is empty by default, so nothing inbound is open. Each entry
opens one port, or a range with `port_max`, over TCP or UDP to the listed source
CIDR blocks:

```hcl
published_ports = {
  https = {
    protocol     = "tcp"
    port         = 443
    source_cidrs = ["0.0.0.0/0"]
    description  = "HTTPS from the internet."
  }

  internal_api = {
    protocol     = "tcp"
    port         = 8080
    port_max     = 8090
    source_cidrs = ["10.0.0.0/24"]
  }
}
```

An NSG rule carries exactly one source, so an entry becomes one rule per source
CIDR block. `terraform output instance_published_ports` lists what is open.

Adding a port is one map entry, which keeps the reviewable unit of change the
same size as the decision being made. The variable rejects, at plan time:

| Rejected | Reason |
|:---------|:-------|
| A protocol other than `tcp` or `udp` | Ranges are meaningless for the rest, and ICMP is already handled |
| Ports outside 1–65535, or `port_max` below `port` | Malformed range |
| An empty or malformed `source_cidrs` | A rule with no valid source silently opens nothing, or everything |
| Any entry covering port 22 | Otherwise a range spanning 22 would reopen SSH and skip the `0.0.0.0/0` rejection on `ssh_ingress_cidr_blocks` |

### Diagnosing a Port

When something is unreachable, the *way* it fails identifies which layer
dropped it. From off the box, `curl -v --max-time 5 http://<public-ip>:<port>`:

| Symptom | Cause |
|:--------|:------|
| Hang, then timeout | The NSG is not admitting it — the packet never arrived |
| Fast `No route to host` | The packet arrived and the host's iptables rejected it |
| `Connection refused` | It reached the host and nothing is listening on that port |
| HTTP 404 on 80/443 | Traefik answered, but no router matched that `Host` header |

The first two are the pair worth remembering: a timeout means the cloud
firewall, a fast rejection means the host firewall. They are fixed in different
places.

## Compute Instance

One `VM.Standard.A1.Flex` instance running Canonical Ubuntu 24.04 Minimal
(aarch64), in the public subnet with an ephemeral public IP.

| Setting            | Value                  | Always Free allowance                                       |
|:-------------------|:-----------------------|:------------------------------------------------------------|
| Shape              | `VM.Standard.A1.Flex`  | 1,500 OCPU hours + 9,000 GB hours per month                 |
| OCPUs              | 2                      | 2 OCPUs running continuously                                |
| Memory             | 12 GB                  | 12 GB running continuously                                  |
| Boot volume        | 200 GB                 | 200 GB, boot and block volumes combined                     |
| Volume performance | 10 VPU/GB ("Balanced") | The default performance level for a new boot volume         |

**This instance consumes the whole Always Free compute and storage allowance.**
1,500 OCPU hours and 9,000 GB hours per month work out to exactly 2 OCPUs and
12 GB running 24/7, and the 200 GB boot volume is the entire block volume
allowance. There is nothing left over, so anything else you launch in this
tenancy is billed — including the two `VM.Standard.E2.1.Micro` instances the
Always Free tier otherwise offers, whose boot volumes would push storage past
200 GB.

Guardrails in [compute.tf](compute.tf):

- Shape, OCPUs, memory, volume size, and VPUs are `locals`, not variables. Each
  is a billing boundary rather than a preference.
- A precondition fails the plan if `region` is not the tenancy's home region.
  Always Free compute and block volume storage exist only there; the same
  resources elsewhere are billed at the normal rate.
- `preserve_boot_volume = false`, so destroying the instance releases the 200 GB.
  A preserved boot volume keeps consuming the allowance with nothing attached.
- `ignore_changes` on the image OCID. Canonical publishes new 24.04 Minimal
  builds regularly, and without this a routine `apply` would destroy and rebuild
  the server to pick one up.
- No backup policy is attached, so no volume backups are created.

Ampere A1 capacity is often exhausted in a given availability domain. A launch
that fails with "Out of host capacity" is a capacity problem, not a
configuration one: set `availability_domain_number` to 2 or 3 and retry.

**Inbound SSH is closed by default.** `ssh_ingress_cidr_blocks` is empty, so the
NSG admits nothing on port 22 and
`ssh ubuntu@$(terraform output -raw instance_public_ip)` will time out. Set the
variable to the administrator networks that need access:

```hcl
ssh_ingress_cidr_blocks = ["203.0.113.4/32"]
```

`0.0.0.0/0` is rejected by validation. With the list empty, reach the instance
through an Instance Console Connection instead. The OCI Bastion service is not an
option here: its managed SSH sessions target instances in private subnets, and
this instance is in the public one.

## Remote State

State lives in an Object Storage bucket in this tenancy, created by
[state.tf](state.tf) and configured through the backend block in
[terraform.tf](terraform.tf).

The bucket is created by the same configuration whose state it holds, which is a
bootstrap loop and the reason for two deliberate choices:

- It lives in the **tenancy root**, not `free-compartment`, so tearing down the
  compartment never has to delete the bucket describing it.
- `prevent_destroy` is set, so `terraform destroy` fails loudly instead of
  deleting the state store halfway through and stranding the rest of the
  tenancy. Removing that one line is all it takes to tear this down
  deliberately.

The bucket has versioning enabled (state is tens of kilobytes; retained versions
cost nothing against the 20 GB allowance), `NoPublicAccess`, and the `Standard`
storage tier — `Archive` or `Infrequent Access` would make `terraform plan` fail
or bill.

A backend block cannot reference variables, so the tenancy-specific values are
literals in `backend.hcl`, which is gitignored the same way `terraform.tfvars`
is. Copy it from [backend.hcl.example](backend.hcl.example). Credentials come
from the `DEFAULT` profile in `~/.oci/config` rather than being repeated there,
so no API key material sits in the repository directory.

Locking is automatic: the backend writes `<key>.lock` into the same bucket with
`If-None-Match` for every plan, apply, and destroy, so two concurrent runs
cannot both hold it.

## Getting Started

```bash
# 1. Provider credentials.
cp terraform.tfvars.example terraform.tfvars   # then edit

# 2. Bootstrap: create the state bucket while state is still local.
terraform init
terraform apply -target=oci_objectstorage_bucket.terraform_state

# 3. Point the backend at it.
cp backend.hcl.example backend.hcl             # then edit
terraform output objectstorage_namespace       # the value backend.hcl wants

# 4. Migrate state into the bucket.
terraform init -backend-config=backend.hcl -migrate-state

# 5. Everything else.
terraform plan
terraform apply
```

Steps 2–4 are once per tenancy. After that, `terraform init` picks the backend
up from the cached settings in `.terraform/` and the flag is only needed if the
backend configuration itself changes.

Then, on the box: install Dokploy, give it a domain, create the first account,
and remove the `dokploy_dashboard` entry from `published_ports`.

Before committing, run `terraform fmt -recursive` and `terraform validate`.
