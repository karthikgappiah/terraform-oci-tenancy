# AppiahCo — OCI Terraform Repository

This repository contains tenancy-level infrastructure:

1. A compartment named `free-compartment`
2. A network (VCN) with internet connectivity named `free-vcn` generated by the VCN wizard.
3. A compute instance sized to the entire Always Free allowance.

## Network Topology

| Resource                       | Purpose                                                             |
|:-------------------------------|:--------------------------------------------------------------------|
| VCN (`10.0.0.0/16`)            | Regional virtual network in `free-compartment`                      |
| Public subnet (`10.0.0.0/24`)  | Reachable from the internet through the internet gateway            |
| Private subnet (`10.0.1.0/24`) | No public IPs on VNICs                                              |
| Internet gateway               | Bidirectional internet path for the public subnet                   |
| NAT gateway                    | Outbound-only internet path for the private subnet                  |
| Service gateway                | Private path from the private subnet to the Oracle Services Network |

Traffic rules — OCI's default security list rule set on both subnets:

- **Public subnet** — ingress on 22 from `0.0.0.0/0`, ICMP type 3 code 4 from
  `0.0.0.0/0`, ICMP type 3 from the VCN CIDR block. Egress is unrestricted.
- **Private subnet** — the same three rules, except SSH is scoped to the VCN CIDR
  block rather than the internet. Egress is unrestricted.
- Routing: the public subnet defaults to the internet gateway; the private subnet
  defaults to the NAT gateway, with a more specific Oracle Services Network route
  through the service gateway.

The VCN's default route table and default security list are left as OCI creates
them. Nothing in this configuration attaches to them.

## Compute Instance

One `VM.Standard.A1.Flex` instance running Canonical Ubuntu 24.04 Minimal
(aarch64), in the public subnet with an ephemeral public IP.

| Setting            | Value                  | Always Free allowance                                       |
|:-------------------|:-----------------------|:------------------------------------------------------------|
| Shape              | `VM.Standard.A1.Flex`  | 1,500 OCPU hours + 9,000 GB hours per month                 |
| OCPUs              | 2                      | 2 OCPUs running continuously                                |
| Memory             | 12 GB                  | 12 GB running continuously                                  |
| Boot volume        | 200 GB                 | 200 GB, boot and block volumes combined                     |
| Volume performance | 10 VPU/GB ("Balanced") | The default performance level for a new boot volume         |

**This instance consumes the whole Always Free compute and storage allowance.**
1,500 OCPU hours and 9,000 GB hours per month work out to exactly 2 OCPUs and
12 GB running 24/7, and the 200 GB boot volume is the entire block volume
allowance. There is nothing left over, so anything else you launch in this
tenancy is billed — including the two `VM.Standard.E2.1.Micro` instances the
Always Free tier otherwise offers, whose boot volumes would push storage past
200 GB.

Guardrails in [compute.tf](compute.tf):

- Shape, OCPUs, memory, volume size, and VPUs are `locals`, not variables. Each
  is a billing boundary rather than a preference.
- A precondition fails the plan if `region` is not the tenancy's home region.
  Always Free compute and block volume storage exist only there; the same
  resources elsewhere are billed at the normal rate.
- `preserve_boot_volume = false`, so destroying the instance releases the 200 GB.
  A preserved boot volume keeps consuming the allowance with nothing attached.
- `ignore_changes` on the image OCID. Canonical publishes new 24.04 Minimal
  builds regularly, and without this a routine `apply` would destroy and rebuild
  the server to pick one up.
- No backup policy is attached, so no volume backups are created.

Ampere A1 capacity is often exhausted in a given availability domain. A launch
that fails with "Out of host capacity" is a capacity problem, not a
configuration one: set `availability_domain_number` to 2 or 3 and retry.

Connect with `ssh ubuntu@$(terraform output -raw instance_public_ip)`. Port 22 is
open to `0.0.0.0/0` because the security lists are the VCN wizard's defaults.

## Local Development

1. Copy `terraform.tfvars.example` to `terraform.tfvars` and fill in your OCI credentials.
2. Run `terraform init`.
3. Run `terraform plan` / `terraform apply`.

Before committing, run `terraform fmt -recursive` and `terraform validate`.
